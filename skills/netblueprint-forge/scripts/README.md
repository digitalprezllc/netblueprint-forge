# scripts/

Node.js 18+, no dependencies. Run from anywhere; paths inside the scripts resolve relative to the skill.

| Script | Does |
| - | - |
| `validate.mjs <model.json> [--fix] [--strict] [--json] [--quiet]` | Checks the model against the schema (built-in draft 2020-12 subset validator), then lints cross-references (unique names, every ref resolves, auth types, layers, phases, requirement and dependency references), status rules (mitigated needs an implemented control, accepted needs an acceptance record) and risk ratings against their inputs. `--fix` writes `risk.rating`, `risk.score` and the OWASP averages/levels back into the file. Exit 0 valid, 1 errors, 2 I/O. Exports `validateModel`, `computeAssessment`. |
| `build.mjs <model.json> [-o out.html] [--template path] [--no-validate]` | Runs the validator, then injects the model into `assets/template/template.html` (JSON in a `<script type="application/json">` slot with `<` escaped) and writes the self-contained HTML next to the model. |
| `archive.mjs <model.json> [--note "…"] [--bump patch\|minor\|major] [--html path] [--dry-run]` | Copies the model and its HTML into `archive/` as `<name>-v<version>_<timestamp>.*`, bumps the version, sets the date and revision note, opens a CHANGELOG entry. Run **before** editing. |
| `archive.mjs <model.json> --diff` | After editing: appends the element-level differences against the latest snapshot to `archive/CHANGELOG.md`. Exports `diffModels`, `snapshot`, `logDiff`, `bump`. |
| `normalize.mjs <field> "<text>"` · `--fields` · `--describe <field>` | Maps what a user typed onto an option list (STRIDE, bands, vulnerability categories, adversaries, statuses, protocols, credential storage, platform, hosting …) with synonyms and fuzzy matching; returns the value, a confidence and the top candidates, and `ask: true` when the skill should confirm. Also powers the validator's "did you mean". |
| `model-reference.mjs [--stdout]` | Regenerates `references/model-reference.md` from the schema. Run after every schema change. |
| `scenario.mjs <model.json> --tab <what-if tab> [--json]` | The delta of a what-if scenario tab against its baseline tab: elements added, removed and changed per collection, boundaries and exposure that changed, controls invalidated or orphaned, threats and attack paths added, removed or moved. Markdown by default. Exit 2 when the tab is not a scenario. |
| `check.mjs <built.html> [more.html …] [--browser <exe>] [--max-crossings N] [--max-bends N] [--json]` | Opens a built page headless in a Chromium-based browser already on the machine (Chrome, Chromium, Brave, Playwright's; `--browser` or `NB_BROWSER` for other paths), lets the page run its own geometry check on every diagram tab and fails on the hard checks: a line through or within 8 px of a box it does not touch, over text, a glyph clash, a jog, two lines in one lane, an unrouted leg. Prints crossings and the longest flow's bends per tab. Exit 0 pass, 1 fail, 2 no browser or no report. Exports `findBrowser`, `runReport`, `judge`. |
| `screenshot.mjs <built.html> [-o out.png] [--tab <name>] [--step <n \| step name>] [--path AP-nnnn [--hop n]] [--width 1600] [--height auto\|N] [--scale 1]` | Renders one view of a built page to a PNG with the same browser: the tab, walkthrough step or attack-path hop asked for (the page's own deep links, `#tab=…&step=…`), the whole page at the diagram's natural size unless `--height` fixes it; `--scale 2` for crisp pictures in documents and decks. Exports `screenshot`, `deepLinkHash`. |
| `icons.mjs search <text> [--provider p]` · `fetch dashboard/<name> … --model <model.json>` · `list [provider] [--kind k]` · `check <model.json>` · `stats` · `import <provider> <package.zip> …` | The vendor icon library (`assets/icons/<provider>.json`: the official Microsoft Azure and Entra, AWS and Google Cloud icons) and product logos fetched on demand. `search` answers "which id" for an `icon` value such as `azure/key-vaults`, and with `--provider dashboard` searches the Dashboard Icons catalogue online; `fetch` downloads one logo (jsDelivr, then GitHub), refuses scripts, event handlers and external references, normalizes it and stores it in `icons.json` beside the model, where `build.mjs`, `validate.mjs` and `check` read it; `check` lists a model's vendor icons and any that the library lacks; `import` rebuilds an index from a vendor package (reads the ZIP itself, keeps one size per icon, prefixes ids and classes, changes nothing else). `build.mjs` injects only the icons a page uses. Exports `resolveIcon`, `collectIcons`, `cardIcons`, `normalizeSvg`, `symbolMarkup`, `fetchIcons`, `useLocalIndex`. |
| `suggest.mjs <model.json> [--apply] [--json] [--rule R001,R002] [--tab <name>]` · `--rules` | Threat enumeration by rule (`rules.mjs`, 23 rules: STRIDE per interaction over the flows and elements). Lists candidate threats with STRIDE, CWE, ATT&CK, an adversary, a default rating and a mitigation; skips what the model already covers on the same target; `--apply` appends them as `suggested: true` with `suggested_from: "rule:Rnnn"` and the next free THR numbers. What-if tabs are skipped. |
| `report.mjs <model.json> [--kind exec\|developer\|audit\|all] [-o out.md]` | Markdown reports from the model: the executive summary (risk at a glance, open threats, attack paths, accepted risks, policy), the developer list (planned controls by owner with due dates, tickets, the threats they close and the requirements they satisfy; unconverted mitigations; open threats with no plan; validator warnings), the audit view (verified controls with evidence, requirements by framework clause, accepted risks, every threat and its controls). |
| `portfolio.mjs <folder \| model.json …> [--no-recursive] [--json] [-o out.md]` | One table across every `*.model.json` under a folder (`archive/` skipped): threats by current band, open threats at high or above, attack paths, controls planned and overdue, requirements verified, the policy result and the validator result per document, with totals. |

`--strict` adds `settings.policy` over its defaults (open threats at a band with no planned control on track, missing treatment decisions, overdue controls, verified controls without evidence when asked, requirements without controls, suggested elements, accepted risks past review) and reports each failure as `error: policy: …` with exit 1, so CI can gate on the model.

Tests at the repository root: `node tests/check_validate.mjs` (validator, policy, risk computation), `node tests/check_suggest.mjs` (every rule on a fixture, the examples, `--apply`), `node tests/check_reports.mjs` (the three reports and the portfolio on the examples).
